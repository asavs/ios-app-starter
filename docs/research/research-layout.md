# Research layout proposal

Checked 2026-10-27. Recommendation for Asa: keep topic reports under `docs/research/` for now, with a short module README linking to its relevant report and an index from `docs/modules.md`. Research crossing modules, including audio policy and session timing, remains discoverable in one place. Add pointers to this convention in `AGENTS.md` only after the choice is accepted. This PR does not move existing files or change that convention.

A per-module `RESEARCH.md` places decisions beside source and travels with a tagged module, but cross-cutting research has no obvious owner and duplication can drift. A shared `refs/` bibliography with stable IDs centralizes metadata but adds indirection and maintenance; it is useful when the same sources recur extensively, not required for a small collection. Current reports use direct links, checked dates and evidence grades; record titles and specific claims near each link. When a useful legal and accessible archive snapshot exists, link it alongside the original and record its capture date; do not assume every page can or should be archived. Periodically recheck links and version-sensitive claims when a module changes.

Tagged Swift packages contain repository documentation in the source checkout, but consuming a binary or browsing package API documentation does not ensure a generated app sees it. Link module README and release notes to version-pinned repository URLs and include research in app onboarding guidance. Verify the generated-app path in the milestone 10 proof. The owner can choose another layout without forcing a file move in this research PR.
