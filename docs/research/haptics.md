# Haptics

Checked 2026-10-27. A: Apple. Recommendation: app-specific phase-event mapping, shared only when another app needs it. SwiftUI `sensoryFeedback` (iOS 17+) expresses feedback from a state trigger; UIKit concrete `UIFeedbackGenerator` subclasses suit imperative events, and Core Haptics is for custom patterns on supported hardware. Apple recommends short, meaningful haptics and an off switch, and notes standard controls already supply feedback ([HIG, A](https://developer.apple.com/design/human-interface-guidelines/playing-haptics), [UIKit, A](https://developer.apple.com/documentation/uikit/uifeedbackgenerator)). Do not rely on haptics as the only phase signal; support varies by device and system settings. Prepare generators where appropriate and test on a physical iPhone, including pause and resumed sessions. Haptics cannot be assumed to fire during app suspension.

The system decides whether feedback plays based on hardware, foreground state and settings; a trigger is a request, not delivery confirmation ([Apple, A](https://developer.apple.com/documentation/applepencil/playing-haptic-feedback-in-your-app)). A developer tutorial demonstrates the iOS 17 modifier and cautions against overuse ([SerialCoder, B](https://serialcoder.dev/swiftui/enabling-haptic-feedback-with-sensoryfeedback-in-swiftui/)). Test rapid phase changes for unwanted repetitions.
