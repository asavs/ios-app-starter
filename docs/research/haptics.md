# Haptics

Checked 2026-10-27. A: Apple. Recommendation: a haptic adapter in the optional cue module can serve interval timers, guided exercises and productivity apps; hosts choose event semantics. SwiftUI `sensoryFeedback` (iOS 17+) expresses feedback from a state trigger; UIKit concrete `UIFeedbackGenerator` subclasses suit imperative events, and Core Haptics is for custom patterns on supported hardware. Apple recommends short, meaningful haptics and an off switch, and notes standard controls already supply feedback ([HIG, A](https://developer.apple.com/design/human-interface-guidelines/playing-haptics), [UIKit, A](https://developer.apple.com/documentation/uikit/uifeedbackgenerator)). Do not rely on haptics as the only phase signal; support varies by device and system settings. Prepare generators where appropriate and test on a physical iPhone, including pause and resumed sessions. Haptics cannot be assumed to fire during app suspension.

The system decides whether feedback plays based on hardware, foreground state and settings; a trigger is a request, not delivery confirmation ([Apple, A](https://developer.apple.com/documentation/applepencil/playing-haptic-feedback-in-your-app)). A developer tutorial demonstrates the iOS 17 modifier and cautions against overuse ([SerialCoder, B](https://serialcoder.dev/swiftui/enabling-haptic-feedback-with-sensoryfeedback-in-swiftui/)). Test rapid phase changes for unwanted repetitions.

## Adapter design

The cue module can expose `HapticOutput.play(event:)` with semantic phase-start and completion events; host mapping selects a system style. For a SwiftUI-only interaction, `sensoryFeedback` binds feedback to an Equatable trigger; an imperative coordinator can instead use concrete UIKit generators. Core Haptics supports custom patterns but requires hardware capability checks and engine lifecycle handling. Do not create a custom pattern merely to reproduce system feedback. The app's Settings binding enables or disables the adapter and a fake records events in tests. The demo shows a phase transition and a haptics toggle, plus text/audio alternatives and VoiceOver-accessible state. Verify on supported hardware: system settings and foreground state decide whether a request plays.

[Haptica](https://github.com/efremidze/Haptica) (MIT, B) wraps predefined generators and documents device/foreground constraints. [Haptico](https://github.com/iSapozhnik/Haptico) (MIT, B) adds patterns. [SwiftfulHaptics](https://github.com/SwiftfulThinking/SwiftfulHaptics) (MIT, B) offers system and custom patterns. These are API comparisons, not endorsements; none establishes background delivery. Apple's [sensoryFeedback API](https://developer.apple.com/documentation/swiftui/view/sensoryfeedback%28trigger%3A_%3A%29), [HIG](https://developer.apple.com/design/human-interface-guidelines/playing-haptics) and [Core Haptics](https://developer.apple.com/documentation/corehaptics) are authoritative for their respective capabilities (A).
