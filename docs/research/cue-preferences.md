# Cue preferences

Checked 2026-10-27. A: Apple and repository implementation. Recommendation: a reusable cue preferences section composes with the existing Settings module; apps choose defaults and non-secret key names for sound, countdown, voice and haptics. `SettingsView` accepts `@ViewBuilder extra` between Appearance and About; `StarterSettingsView` demonstrates it. Register defaults at every launch: the registration domain is volatile and falls back behind stored values ([Apple, A](https://developer.apple.com/documentation/foundation/userdefaults/register(defaults:))). Keep `@AppStorage` defaults and registered values consistent, test absent and explicitly false values, and inject a separate defaults suite in tests. Define how countdown depends on sound without silently rewriting the user's preference. Keep secrets in Settings' Keychain abstraction. `@AppStorage` and this design support iOS 17.

## Shared settings section

Expose a `CuePreferences` value and `CuePreferencesSection` accepting bindings or an injected preference store, key namespace and defaults. Workout, meditation and focus apps can reuse it while choosing which controls are meaningful. Compose it in `SettingsView { CuePreferencesSection(...) }`; Theme styles the host form, and the coordinator reads a policy snapshot. Keep the standalone cue engine independent of SwiftUI and Settings. Demo all four toggles and a test cue, including disabled-notification messaging. Labels must explain meaning without relying on color; verify VoiceOver and Dynamic Type. UserDefaults' [registration](https://developer.apple.com/documentation/foundation/userdefaults/register%28defaults%3A%29), [domain order](https://developer.apple.com/documentation/foundation/userdefaults) and [settings guidance](https://developer.apple.com/documentation/foundation/accessing-settings-from-your-code) are primary sources (A). [WorkoutTimer](https://github.com/wollodev/WorkoutTimer) separates persisted feedback preferences from timing (MIT, B); [Haptica](https://github.com/efremidze/Haptica) shows independently selected feedback types (MIT, B). Neither establishes a shared public settings API.
