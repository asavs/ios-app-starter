# Keeping the run screen awake

Checked 2026-10-27. A: Apple. Recommendation: propose an optional screen-awake coordinator for timers, navigation and cooking apps; the host decides when a visible session merits it. Set `UIApplication.shared.isIdleTimerDisabled` only during an active, visible run when the person benefits, then clear it on pause, exit, scene inactivity and interruption as appropriate. The property is app-wide, so centralize ownership and account for multiple scenes or overlapping users of the setting; avoid an unconditional cleanup that cancels another owner's request. Apple's documentation warns to disable the idle timer only when necessary because of power cost ([Apple, A](https://developer.apple.com/documentation/uikit/uiapplication/isidletimerdisabled)). Verify lock behavior and restoration on a physical device. This does not prevent manual locking or grant background execution. Available on iOS 17.

## Coordinator design

A cooking timer, navigation view or workout can use a `ScreenAwakeCoordinator` with scoped acquire/release tokens, keyed by active foreground scene and feature. Tokens avoid one feature clearing another's active request; deinitialization alone is not a sufficient lifecycle contract. The app injects a fake idle-timer setter in tests and verifies pause, disappearance, background and two simultaneous owners. The demo shows an active-session switch and explanatory status, accessible to VoiceOver. This coordinator composes with the session module without depending on cues, Settings or Theme; hosts choose whether to offer a preference. The iOS 17 system property is app-wide, so multi-scene policy requires real device verification.

Apple documents the [idle timer property](https://developer.apple.com/documentation/uikit/uiapplication/isidletimerdisabled) and [scene phase](https://developer.apple.com/documentation/swiftui/scenephase) (A). [WorkoutTimer](https://github.com/wollodev/WorkoutTimer) provides an interval-app comparison (MIT, B); [WODrounds](https://github.com/JarlLyng/WODrounds) documents its iOS idle-timer policy (MIT, B). These implementations are references, not proof of correct multi-scene ownership. A screen-awake request cannot prevent manual locking.
