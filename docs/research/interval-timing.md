# Interval timing

Built as the `SessionTimer` module (2026-10-27); see [modules.md](../modules.md#sessiontimer) for what shipped and what is still open.

Checked 2026-10-27. A: Apple documentation; B: independent practitioner. Recommendation: propose an optional clock-driven session module for workouts, Pomodoro and meditation. The host owns its phase content and cue policy.

A `ContinuousClock` anchor plus phase boundaries derives elapsed time from the clock rather than adding 50 ms on each wake. Apple contrasts this clock, which advances during device sleep, with `SuspendingClock`, which stops while the machine sleeps ([WWDC22, A](https://developer.apple.com/videos/play/wwdc2022/110355/)). A wake loop is only a sampling mechanism: scheduling, suspension and tolerance mean it is not a deadline guarantee. Derive current phase on resume, decide explicitly whether to skip or coalesce missed cues, and track cue IDs to avoid duplicate playback after a late wake. Inject a controllable clock to test exact boundaries, pauses, multiple missed phases and cancellation. A monotonic instant should not be treated as a durable wall-clock timestamp across reboot or process death; persist an appropriate wall-clock deadline and session state separately if recovery is required, with a policy for clock changes.

`Task.sleep` suspends a task, can be cancelled and accepts tolerance; a 50 ms loop has power costs and no hard real-time guarantee ([Swift Clock API, A](https://developer.apple.com/documentation/swift/clock)). `TimelineView` schedules view updates and `Timer.publish` emits run-loop events; neither should be the source of truth or assumed to run in background ([TimelineView, A](https://developer.apple.com/documentation/swiftui/timelineview), [Timer publisher, A](https://developer.apple.com/documentation/foundation/timer/publish(every:tolerance:on:in:options:))). Stop unnecessary updates when inactive. Continuous time remains correct while suspended, but code and cues do not execute then. See [background cues](background-audio.md).

Point-Free's open-source `TestClock` demonstrates advancing injected time deterministically ([article, B](https://www.pointfree.co/blog/posts/82-open-sourcing-swift-clocks)); its authors also discuss concurrency scheduling pitfalls in async tests ([discussion, B](https://www.pointfree.co/episodes/ep239-reliable-async-tests-more-problems)). Evaluate the dependency separately rather than assuming it belongs in the starter.

## Proposed session module

For a Pomodoro app, phases might be 25 minutes focus and 5 minutes rest; a meditation app might have lead-in, practice and closing bell; Val Time supplies hold/rest names and durations. Sketch: `SessionPlan(phases: [Phase], repetitions: Int)`, `SessionClock(clock: injectedClock, plan: SessionPlan)`, and `start`, `pause`, `resume`, `stop`, `snapshot(at:)`. A snapshot contains phase ID, phase elapsed, total elapsed, remaining and state. An event stream can expose phase crossings with stable IDs; the consumer chooses whether missed events are skipped or summarized. No UI, audio, Settings or SwiftData dependency belongs in the engine. The app persists an optional recovery representation and creates cue schedules; the ring consumes snapshots and Theme supplies colors.

Define zero or negative durations, repeat bounds, pause accounting, crossing multiple boundaries, cancellation, clock discontinuity on restoration, and completion exactly once. Use monotonic time for live elapsed duration and a separately documented wall-clock restoration strategy, because instants are not a durable cross-reboot contract. Inject the clock, avoid unbounded high-frequency observers, and derive rather than increment state. Tests advance a controlled clock across pauses and multiple transitions, ensure cancellation and event deduplication, and separately test app lifecycle on device. Demo two different plans, pause/resume, a ring and a cue log; accessible controls report state without color dependence.
